Clases
 ClaseDescripción
EstadoCancelada Estado Cancelada: estado final, no permite transiciones.
EstadoConfirmada Estado Confirmada: solo permite cancelar.
EstadoExpirada Estado Expirada: estado final, no permite transiciones.
EstadoPendiente Estado Pendiente: permite confirmar, cancelar y expirar.
EstadoReservaState Clase base abstracta del patrón State para los estados de una reserva. Define las transiciones permitidas; las subclases habilitan las que corresponden.
ExpiracionReservasService Servicio singleton con temporizador de fondo que expira automáticamente las reservas vencidas. Implementa los patrones Singleton y Observer. Se enciende al crear una reserva pendiente y se apaga cuando no quedan pendientes.
ListaEsperaBLL Lógica de negocio para la gestión de la lista de espera de slots.
PagoBLL Lógica de negocio para el registro y consulta de pagos. Implementa CU.Sis.002 — Registrar Pago Aprobado.
PoliticaCancelacionPorPlazo Política de cancelación basada en plazo: reembolso total si se cancela con al menos N horas de anticipación (regla cancelacion_gratis_hs del comercio).
ReservaBLL Lógica de negocio principal para la gestión de reservas. Implementa CU.Cli.001, CU.Cli.002, CU.Cli.004, CU.Com.015, CU.Sis.001 y CU.Sis.004.
SlotNoDisponibleException Excepción lanzada cuando un slot ya fue tomado por otro cliente de forma concurrente.
Interfaces
 InterfazDescripción
IPoliticaCancelacion Interfaz del patrón Strategy para la política de cancelación de reservas. Determina si corresponde reembolso al cancelar.
